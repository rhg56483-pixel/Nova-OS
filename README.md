# Dolphin OS 1.0 — تطوير مشروع Nova OS

توزيعة Linux حقيقية مبنية على **Debian 13 / trixie / amd64**. تم تطوير مشروع Nova المرفق، مع الاحتفاظ بنسخته الأصلية للمقارنة في `docs/legacy-nova/`.

**حالة التسليم: مشروع مصدر مع فحوصات ساكنة؛ لم يُبنَ ISO في بيئة التسليم ولم يُختبر الإقلاع أو التثبيت.** لا يوجد ISO داخل هذا ZIP. اسم الناتج عند نجاح البناء: `out/DolphinOS-x86_64.iso`.

## البداية على GitHub للمبتدئ

1. فك ZIP. افتح مجلد المشروع الذي يحتوي على `build.sh` و`config` و`.github`.
2. ارفع **محتويات هذا المجلد إلى جذر المستودع**، لا ترفع ZIP وحده ولا تجعل الملفات داخل `nova-os/` إضافي. الطريقة الأضمن Git كما في `docs/GITHUB.md`؛ الرفع بالسحب قد يُسقط المجلد المخفي.
3. يجب أن يظهر المسار `.github/workflows/build-iso.yml` في صفحة **Code** على الفرع الافتراضي `main`.
4. فعّل Actions من Settings → Actions → General إن كانت معطلة.
5. افتح Actions → **Build Dolphin OS ISO** → **Run workflow** → Run workflow.
6. انتظر اكتمال الخطوات. إن فشل البناء افتح الخطوة الحمراء ثم ملف السجلات؛ لا توجد عبارة نجاح لمجرد انتهاء سكربت فرعي.
7. نزّل Artifact باسم `DolphinOS-x86_64-رقم`، وفك ضغطه. شغّل `join-iso.ps1` على Windows أو `bash join-iso.sh` على Linux لإعادة تجميع ISO والتحقق من SHA256.

الملف الأصلي كان يحتوي على Workflow يدوي صحيح من حيث المبدأ. صفحة Get started وحدها لا تثبت أن YAML معطوب؛ من الأسباب المحتملة فقدان `.github` أو وضعه داخل مجلد متداخل أو رفعه إلى فرع غير افتراضي. لم نفحص مستودعك نفسه.

## البناء محليًا

استخدم Debian **13** بمعمارية amd64، نظام ملفات Linux محليًا، وصول إنترنت إلى مستودعات Debian، و20 GiB مساحة فارغة على الأقل للعمل إضافة إلى مساحة حفظ ISO. قد تحتاج مساحة أكثر؛ لا يوجد زمن بناء مقاس لهذا المشروع.

```bash
sudo bash build.sh
```

أو Linux / WSL2 مع Docker يعمل وصلاحيات للحاويات المميزة:

```bash
bash docker-build.sh
```

الحاوية `debian:13` تحتاج `--privileged` لأن live-build يستخدم mount وchroot. لا تستخدم NTFS أو مجلد مشاركة VirtualBox للبناء. السكربت يرفض مضيفًا غير Debian 13 بدل الادعاء بالتوافق.

تُحفظ سجلات كامل البناء في `out/build.log`. تُترك مساحة العمل المؤقتة في `/var/tmp/dolphin-build.*` للتشخيص. بعد الفشل تأكد من إلغاء mounts داخلها قبل حذفها. لا يحذف السكربت أي مسار يحدده المستخدم. الحزم وإصداراتها تتغير مع تحديثات Debian؛ البناء غير قابل لإعادة الإنتاج بتطابق البايتات دون snapshot ومزيد من التثبيت بالإصدارات.

## سطح المكتب الحقيقي

- LXQt + Openbox على X11؛ مدير الملفات PCManFM-Qt، طرفية QTerminal، مدير مهام Qps، إعدادات LXQt، إشعارات، إدارة الطاقة وUSB.
- شريط سفلي بنفسجي داكن وقائمة تطبيقات وقائمة بحث LXQt Runner، أيقونات Papirus، شعار دولفين SVG أصلي وخلفيات SVG مع PNG بدقة HD و4K تُولد أثناء البناء.
- SDDM بواجهة Debian elarun الأصلية وخلفية Dolphin، وPlymouth بشعار ثابت. النوافذ لها إطار Openbox مخصص. **لم نضف compositor أو blur أو تدوير زوايا النوافذ** حفاظًا على الخفة؛ زوايا بعض أزرار اللوحة فقط مستديرة.
- الشبكة: NetworkManager وnm-applet؛ الصوت: PipeWire وWirePlumber وpavucontrol-qt. Bluetooth عبر Blueman حسب العتاد.
- Firefox ESR بالعربية، FeatherPad، MPV، عارض صور، أدوات ضغط، Synaptic للتطبيقات والتحديثات، Flatpak وFUSE للتوافق مع AppImage.
- Chromium اختياري من APT، Brave من مستودعه الرسمي، Flathub يضاف باختيار المستخدم. راجع `docs/APPS.md`.
- لا خدمة فهرسة بحث ثقيلة ولا preload ولا تعطيل لتحديثات Debian أو خدمات الأمان. لا نفترض استهلاك RAM معينًا.

## العربية والإنجليزية

`ar_SA.UTF-8` افتراضي، `LANGUAGE=ar:en`، منطقتك الزمنية Asia/Riyadh، لوحة `ara,us` وAlt+Shift، خطوط Noto وAmiri، ترجمة Firefox وQt الرسمية. RTL تابع لدعم البرنامج نفسه وتوفر الترجمة الرسمية؛ النص غير المترجم قد يظهر بالإنجليزية. لا نفرض قلب واجهات لا تدعم RTL.

بعد الإقلاع افتح **اختبار عرض العربية** ثم FeatherPad وFirefox وافحص اتصال الحروف والنص المختلط والأرقام. هذه خطوة بشرية مطلوبة؛ فحص XML/الخطوط لا يثبت صحة تشكيل الحروف على الشاشة. التواريخ والأرقام تتبع locale والتطبيق؛ تعديل اللغة والمنطقة من إعدادات LXQt متاح.

## تجربة Live والتثبيت

المستخدم Live: `dolphin`؛ كلمة مرور live-config الافتراضية: `live` (تحتاج تأكيدًا في أول إقلاع). تسجيل Live تلقائي؛ الحساب المثبت ينشئه المستخدم وكلمة مروره لا تقل عن 8 أحرف.

شغّل أيقونة **تثبيت Dolphin OS**. ينطلق Calamares عبر wrapper Debian وpkexec، وتستند خطواته إلى إعدادات `calamares-settings-debian` المثبتة لا ملفات مختصرة مكتوبة عشوائيًا. يحتفظ المشروع بمسارات Debian لـ mount/unpackfs/fstab وتهيئة مصادر APT وإعادة إنشاء initramfs وGRUB.

قبل إنشاء الحساب الجديد يُحذف الحساب Live إن نُسخ، وتزال إعدادات الدخول التلقائي وامتيازاته ومختصر المثبت. ثنائيات GRUB لـ BIOS وUEFI موجودة مسبقًا لتجنب طلب حزمة bootloader من الشبكة أثناء التثبيت. إزالة الحزم المؤقتة يستخدم تسلسل Debian. **التثبيت بدون إنترنت، إعادة الإقلاع وحفظ الملفات لم تُختبر بعد**.

للنسخة الأولى اختبر تثبيت **ext4 غير مشفر** على قرص VM فارغ. الخيارات المتقدمة مثل التشفير والتثبيت المزدوج لا تُعتبر مؤهلة قبل اختبار مستقل. Live لا يحفظ الملفات بين مرات الإقلاع افتراضيًا؛ حفظ الملفات المقصود يكون بعد التثبيت على القرص.

## VirtualBox

طريقة Windows اليدوية الآمنة للمبتدئ:

1. أنشئ VM جديدة: Linux / Debian 64-bit، مع تعطيل التثبيت غير المراقب.
2. RAM: 2048 MiB لاختبار الحد المستهدف لسطح المكتب الأساسي، أو 4096 MiB للتثبيت والمتصفح؛ المعالج 2 CPU، قرص 32 GiB أو أكبر.
3. الشاشة VMSVGA و128 MiB ذاكرة فيديو، شبكة NAT، صوت Intel HD Audio.
4. أرفق ISO بوحدة DVD. اختبر BIOS أولًا، ثم VM منفصلة مع Enable EFI لاختبار UEFI. عطّل Secure Boot؛ لم نؤهله.
5. أقلع Live، اختبر الشبكة والصوت والإعدادات، ثبّت على قرص VM، أطفئ الجهاز وافصل ISO ثم أقلع من القرص.
6. أنشئ ملفًا بعد التثبيت، أعد التشغيل وتأكد أنه باقٍ. اختبر كلمة المرور وعدم الدخول التلقائي وطلب كلمة مرور sudo.

يتوفر أيضًا `scripts/create-vbox-vm.sh` و`scripts/create-vbox-vm.ps1`. لا تعِد تشغيلهما على VM تحمل الاسم نفسه. راجع `docs/QA.md` لاختبارات QEMU.

حزم `virtualbox-guest-utils` و`virtualbox-guest-x11` غير متاحة في فهارس trixie التي فُحصت؛ حذفنا الاعتماد المكسور وأبقينا دعم العتاد من النواة وXorg. تغيير الدقة الأساسية مطلوب اختباره؛ الحافظة والسحب والإفلات والمجلدات المشتركة تحتاج Oracle Guest Additions اختياريًا بعد التثبيت. لا يوجد ادعاء أنها جاهزة مسبقًا.

## حدود التنزيل

ISO يقسم إلى أجزاء حجمها 1900 MiB، مع hashes للأجزاء وللملف المجمع. هذا يبقي كل أصل Release تحت 2 GiB؛ **التقسيم لا يتجاوز حصة مساحة Actions**. الاحتفاظ بالأصول 7 أيام والضغط معطل لأن ISO مضغوط أصلًا.

إذا انتهت حصة Artifact، أعد التشغيل مع `draft_release=true` لإنشاء **Release مسودة** بملفات الأجزاء. المسودة تحتاج صلاحيات كتابة المحتوى وسياسة مستودع تسمح بذلك. إن فشلت الطريقتان، البناء المحلي هو البديل. لا يتم إنشاء Release الآن؛ هذا خيار عند تشغيلك Workflow.

## الاختبارات والتقارير

- `docs/FIXES.md`: مشاكل الأصل وما تغير وأسبابه.
- `docs/TEST-RESULTS.md`: نتائج الفحوصات التي أُجريت فعليًا وحدودها.
- `docs/FEATURES.md`: ما نُفذ وما ينتظر تجربة فعلية.
- `docs/QA.md`: خطة اختبار BIOS/UEFI والتثبيت والعربية والموارد.
- `scripts/validate.sh`: Bash + ShellCheck + YAML/XML + فحوصات بنية.
- `scripts/check-packages.sh`: أسماء الحزم ومحاكاة حل اعتماديات APT على Debian 13.
- `scripts/verify-iso.sh`: لا نجاح إلا مع ISO موجود يحتوي مدخل BIOS وUEFI وMBR ونواة/initrd وSquashFS وإعدادات LXQt/المثبت. هذا **فحص بنية وليس اختبار إقلاع**.

الاسم 1.0 يصف نسخة المشروع المصدر؛ لا يعني أنها إصدار نهائي مختبر ومؤهل للأجهزة الحقيقية.
